# ip-assess 改善作業の要約

## 概要

不審なアクセス元IPを調査するために作成した bash スクリプト「ip-assess」（GitHub: `yoshihicode/ip-assess`）を、段階的に改善した記録です。

- **位置づけ**：インシデント調査の初動向けツール（フリーソフトとして公開）。判定結果は「安全／危険」の結論ではなく、**調査優先度** と、その根拠を示す
- **前提**：`jq` に依存しない（awk だけで JSON を解析）。APIキーが不要なデータソースを優先する
- **最終バージョン**：1.6.0

## 現在の判定ロジック

### 2軸の評価

| 軸 | 評価方法 | 主な項目 |
| :--- | :--- | :--- |
| 回線種別（インフラ属性） | 加点・減点（インフラスコア） | 国内一般回線 -5、SASE -5、検証済みクローラー -5、データセンター +3、IP転貸 +3、匿名化VPN +3、私書箱 +2、仮想ロケーション +2、PA +1、使える逆引きなし +1 |
| 脅威の評判 | 検出の有無（点数なし。減点で打ち消されない） | Tor 出口ノード、Spamhaus ZEN（SBL/CSS/XBL/DROP）、IPsum（3件以上）、Shodan の乗っ取りタグ、公開プロキシ、偽装クローラー |

2軸に分けた理由：感染した家庭のPC（国内ISP -5 ＋ ブラックリスト登録）が、合算すると「低リスク」に見えてしまう問題を防ぐため。

### 調査優先度

| 優先度 | 条件 |
| :--- | :--- |
| HIGH | 脅威シグナルを検出、またはインフラスコアが 4 点以上 |
| MEDIUM | インフラスコアが 1〜3 点 |
| LOW | 上記以外。「LOW は安全という意味ではない」という注意書きを表示 |

### 主な設計判断

- **判定不能は「Unknown」と表示し、加点しない**。完了できなかったチェックは `Confidence: PARTIAL` として列挙する
- **国内一般回線の判定**：FCrDNS 検証済みの逆引き → 一般家庭向けISPのASN（AS4713・2516・17676・9605 など）→ ASN が取れない場合のみ組織名、の順。備考欄は使わない
- **SERVFAIL の切り分け**：ルートサーバーの正引きでリゾルバの健全性を確認。相手側の不具合なら「使える逆引きなし」として扱う
- **私書箱判定**：組織・グループの住所が該当した場合のみ +2。個人の住所だけなら Info
- **IPsum**：3件以上のリストに掲載で脅威シグナル、1〜2件は Info。ファイルは `~/.cache/ip-assess/` に12時間キャッシュ
- **公開プロキシ（ポート 1080・3128・8118・9050）は脅威シグナル**：家庭の回線では住宅用プロキシや乗っ取られた機器の手がかりになるため

## 出力

- **テキスト**：サマリー → NETWORK → LOCATION → CONTACTS → EXPOSURE → INFRASTRUCTURE ATTRIBUTES → THREAT REPUTATION →（DETAILS）→ DATA SOURCES
- **記号**：標準は絵文字（🔴 🟡 🟢 🔵 ⚪ ❔）、`--plain` で ASCII（`[!]` `[~]` `[o]` `[i]` `[ ]` `[?]`）。セクション見出しには絵文字を使わない
- **値は省略しない**：端末の幅を超える場合は字下げして折り返す。個人の住所も種別（`individual` など）を付けてそのまま表示
- **ヘッダー**：ツール名と実行日時のみ（バージョンは `--version` と JSON の `tool.version` で確認）
- **JSON**：`--json` で機械可読形式。絵文字は含まない

## 調査した事例

### 69.5.174.26

- 英国の回線・IP貸し事業者 Hydra Communications（AS58325、Abuse 窓口は zare.com）の帯域
- 運営者は geofeed で「東京」と申告（`69.5.174.0/24,JP,JP-13,Tokyo,`）。この /24 は登録から33日と新しい
- 現在の NordVPN のサーバー一覧（7,172件）には含まれていない
- 結論：一般家庭の回線ではなく、VPN・プロキシ・ホスティングの可能性。特定にはアクセスログでの振る舞いの確認が必要

### 103.11.121.89

- AS2914（NTT の国際基幹網）上で、海外の住所（私書箱）を持つ事業者が転貸しているホスティング帯域と推定
- Spamhaus SBL に掲載、逆引きは相手側で SERVFAIL
- この事例から、備考欄の「NTT Communications」による国内ISPの誤判定（-5点）が見つかり、v1.3.1 で修正

## 検討して見送った案

- **Cloudflare Workers での API 化**：Ping が使えない、Spamhaus を DoH 経由で使えない（DQS が必要）、認証とレート制限が必須、などの制約がある。調査用途なら応答時間（初回1〜2秒程度の見込み）は問題にならない
- **ブラウザで動くクライアントサイド版**：CORS の制約で DNSBL・geofeed・Ping が実行できず、調査の網羅性が下がる
- **結論**：bash 版を発展させる
- **Web サービスの表示の参考**：見せ方（結論を先頭に、全項目の一覧）は取り入れ、単一スコアや、エラーを「登録あり」と表示する判定は取り入れない
